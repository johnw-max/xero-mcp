# 本轮整改的边界

写在六路审查交付**之前**,以免被 findings 牵着走。审查会挖出很多东西,
但"挖出来"和"这一轮修"是两回事。

---

## 准入判据

一条发现进入本轮修复计划,必须满足下面**至少一条**:

1. **它让一个会计核心动作无法执行** —— 见下"核心动作"定义
2. **它让一个当前可触达的行为是错的** —— agent 今天能走到,而结果不对
3. **它让一个当前可触达的行为无法被证明** —— 结果可能对,但我们说不清
4. **它让问题不可见** —— 缺陷能在这里长期潜伏而没人发现

四条都不满足的,**记录为路线图,不进本轮**。

## 什么算"会计核心动作"(2026-08-20 修订)

先前这份文档把 6 个已注册但不可触达的动作划为"能力广度、路线图"。**那是错的。**
改联系人地址、开报价单、录手工日记账,是会计日常工作本身,不是锦上添花。
一个做不到这些的记账助手,对事务所没有意义。

**判据:凡是草稿态、不直接移动资金的会计动作,都属于核心,本轮必须能执行。**
既包括账本事件(报价单、采购单、手工日记账),也包括客户/主数据维护
(联系人、商品)。

**唯一的例外是碰钱的:** 付款、银行交易、银行转账、批量付款、各类分配、
费用报销单。它们不做,理由是风险而非工作量——这些对象在 Xero 里**没有草稿态**
(`Payment.StatusEnum` 只有 `{AUTHORISED, DELETED}`),而本服务器全部安全架构
建立在"草稿是钱真正动之前最后一道检查点"之上。没有检查点,回读只能在钱已经
动了之后确认。

## 明确不进本轮

| 类别 | 为什么 |
|---|---|
| **资金移动类写入** —— 付款、银行交易、转账、批量付款、分配、费用报销单 | 没有草稿态,与本服务器的安全模型不兼容。**因风险排除,不是因工作量** |
| **只读报表广度** —— Journals、P&L、资产负债表、账龄、Bank Transfers | 缺它们不影响任何写入动作能否执行。**排在写入之后**,不在本轮硬性范围 |
| **评审子系统内部质量** | 已降级为按需诊断,它的内部问题不再影响发布 |
| **能工作的东西的重写** | "风格不一致"不是准入理由 |
| **测试套件的美化** | 弱断言、重复覆盖——除非它正在掩盖一个真缺陷 |

## 已知会撞到的边界情况,先定调

- **含税单据无法开贷项**:满足判据 1(可触达且结果错误) → **进本轮**
- **`harness/` 不在类型检查内**:满足判据 3(缺陷已在此潜伏一周) → **进本轮**
- **手工日记账不适配事实模型**:不可触达,属能力广度 → **不进本轮**
- **字段级失配上报**:满足判据 2(写入结果无法被 agent 理解和纠正) → **进本轮**
- **主数据维护面**:新能力面 → **不进本轮**

## 合成时的纪律

1. **findings 数量不等于计划长度。** 大部分发现应当落在"记录"而非"修复"。
2. **每条进入计划的修复,要写明它满足哪一条判据。** 写不出来的,退回记录。
3. **不做"顺手一起改"。** 顺手是本轮所有返工的来源。
4. **修复的验证方式必须在计划里写死** —— 用什么证据证明修好了,而不是"跑一下测试"。

## 2026-08-20 补记:类型检查覆盖的实测

`tsconfig.json` 的 `include` 只有 `["src/**/*.ts", "config/**/*.json"]`。
vitest 只转译不做类型检查。所以 `tests/**` 和 `harness/**` **从来没有被任何东西
类型检查过**。

实测(把两者加进 include 后跑 `tsc --noEmit`):

| 范围 | 错误数 | 涉及文件 |
|---|---|---|
| `harness/**` | 33 | 6 |
| `tests/**` | 416 | 67 |

### `harness/` —— 进本轮

33 条里有三条不是类型噪音,是**产物在骗人**:

- 合成 provider **比真实 `AccountingProvider` 少 11 个方法**(报价单、采购单等)。
  本地验收闸门一直在验证一个比出厂物更小的接口。
- `authoriseSupplierBill` 被引用两次,**该方法不存在**。
- `FindActiveXeroPostingDuplicateInput` 收到一个它没有的 `actorId` 字段。

满足判据 3(结果说不清)与判据 4(缺陷可长期潜伏)。

### `tests/` —— 不进本轮,记录为路线图

416 条分布在 67 个文件,最大单文件 57 条。按错误码看,
`TS18048`/`TS2532`/`TS7006`(可空索引、回调隐式 any)占相当比例,属人体工学而非缺陷。

**不进本轮的理由**:它不阻塞任何一个会计核心动作(判据 1 不成立),
且本文已明确排除"测试套件的美化"。在 1620 个测试当前仅 2 个红灯(且都已知)
的情况下,横跨 67 个文件的改动带来的失稳风险高于它揭示缺陷的期望收益。

**但这条不能就此消失。** 真正值得单独立项的子集是
"测试构造了一个生产类型不接受的对象"那一类(`TS2345`/`TS2322`/`TS2739`/`TS2740`/`TS2353`
中打到 `src/` 调用点的),因为那意味着**测试绿灯但断言的是生产永远不会产生的形状**。
这正是本仓库出厂五个同类缺陷的机理。下一轮单独做,先分类再动手。
